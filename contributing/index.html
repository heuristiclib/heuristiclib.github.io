On this page

Start contributing ​

This section is for changing HeuristicLib itself. To use the library, start with the guide.

Set up ​

You need the .NET SDK that global.json selects and, for the documentation, Node.js. Then restore and build:

console
dotnet restore
dotnet build --configuration Release --no-restore
1
2

npm ci installs the documentation tools, and npm run docs:dev serves the site locally.

Find your way ​

FolderHolds
src/HeuristicLibThe core package: contracts, algorithms, operators and encodings
src/HeuristicLib.ExperimentalExperimental problems, workflows and features
src/HeuristicLib.PythonInteropThe Python integration
testUnit, scenario, API usage and documentation suites
analyzersRoslyn analyzers for the repository's API rules
docsThis site
samplesRunnable C# applications

Plan the change ​

Planned work and design decisions live in GitHub Issues. Check the related issues before you start, and discuss a change to a public type, a contract or a mechanism before you implement it. Developer guidelines § 2.1 describes how to present a design.

Validate it ​

Run the narrowest tests that give confidence, then widen. The test suite guide says where a test goes and in which order to run the suites.

console
dotnet test --project test/HeuristicLib.Tests/HeuristicLib.Tests.csproj --configuration Release --no-restore
dotnet format whitespace ./HEAL.HeuristicLib.slnx --verify-no-changes --no-restore
1
2

For a documentation change, run npm run docs:build and the documentation tests. Writing documentation covers the rest.

Commit ​

Write each commit message as one imperative line of at most 72 characters, such as Forward root executor controls.
